# Платформа курсів — React, TypeScript та Axios

Каталог курсів із реєстрацією, входом за email і паролем, особистим профілем та записом на навчання. API-функції винесені з компонентів; локальний Node.js API підключений як middleware Vite.

## Запуск

Потрібен Node.js 22.12+.

~~~powershell
npm install
npm run dev
~~~

Відкрийте http://127.0.0.1:5178. У блоці профілю виберіть **«Реєстрація»**, введіть ім’я, email, пароль і його підтвердження. Після реєстрації вхід відбувається автоматично. Для наступного входу використовуйте свій email і пароль.

Збірка, перевірки та preview:

~~~powershell
npm test
npm run build
npm run preview
~~~

Preview доступний на http://127.0.0.1:4178. Завершення сервера — Ctrl+C.

## Вхід і реєстрація

- Перемикання між формами без перезавантаження сторінки.
- Контрольовані поля, autocomplete, показ/приховування пароля.
- Перевірка полів у браузері та незалежна перевірка сервером.
- Ім’я: 2–80 символів; email: коректний формат, до 254 символів; пароль при реєстрації: 10–128 символів; підтвердження має збігатися.
- Email нормалізується до нижнього регістру. Повторна реєстрація відхиляється, включно з одночасними запитами.
- Неправильний email або пароль повертають спільне повідомлення. На вході не повідомляється, чи існує акаунт.
- Під час запиту кнопки блокуються, помилки показуються біля полів або у формі.
- Профіль показує власне ім’я, email та кількість обраних курсів.
- Записи на курси належать окремому користувачу. Повторний запис повертає 409.
- Вихід відкликає сесію на сервері. Перезавантаження сторінки після виходу не відновлює її.

## Збереження даних

Користувачі та їхні курси зберігаються у **demo/.data/users.json**. Цей файл створюється після першої реєстрації, виключений із Git і закритий для завантаження через dev-сервер.

Паролі зберігаються як scrypt-хеші з окремою випадковою сіллю, параметри N=32768, r=8, p=3; порівняння виконується через timingSafeEqual. Відповіді API не містять хешів. Запис файлу відбувається через тимчасовий файл і перейменування.

Після перезапуску сервера акаунти та обрані курси залишаються. Серверні сесії зберігаються в пам’яті, тому після перезапуску потрібен повторний вхід. У звичайній роботі оновлення сторінки відновлює сесію автоматично.

Для ізольованих тестів можна задати шлях до іншого файлу змінною COURSE_DATA_FILE.

Це локальна реалізація для домашнього завдання. Папка dist містить лише frontend; для публічного розміщення потрібен окремо запущений API та HTTPS.

## API-шар

~~~text
src/
  api/
    axiosInstance.ts   # baseURL, timeout, interceptors, ApiError, refresh
    authToken.ts       # Access Token у пам’яті вкладки
    courseApi.ts       # список, деталі, запис на курс
    userApi.ts         # реєстрація, вхід, профіль, вихід
  types/
    course.ts
    user.ts
  components/
    AuthForm.tsx
    CourseList.tsx
    UserProfile.tsx
  App.tsx
demo/
  api.ts               # HTTP-маршрути й перевірка запитів
  userStore.ts         # збереження акаунтів, парольні хеші
  authSessions.ts      # Access Token і HttpOnly сесія
tests/
  auth.test.ts
~~~

Axios має baseURL з VITE_API_BASE_URL (за замовчуванням /api), timeout 8 секунд, JSON-заголовки та withCredentials.

Request interceptor додає поточний Access Token як Authorization: Bearer. Response interceptor централізовано обробляє помилки 400/401/403/404/409/429/5xx, таймаути й мережеві збої. Валідаційні повідомлення сервера передаються формі через типізований ApiError.

Після 401 захищеного запиту interceptor намагається оновити Access Token і повторює запит лише один раз. Одночасні 401 використовують спільний refresh-запит. Вхід і реєстрація не запускають refresh при неправильному паролі. Запит оновлення використовує окремий Axios-виклик, щоб уникнути циклу.

| Метод і шлях після /api | Призначення |
| --- | --- |
| GET /courses | Список курсів |
| GET /courses/:id | Окремий курс |
| POST /auth/register | Ім’я, email, пароль, підтвердження; 201 |
| POST /auth/login | Email і пароль; 200 |
| POST /auth/refresh | Новий Access Token за HttpOnly cookie |
| POST /auth/logout | Відкликання сесії та очищення cookie |
| GET /users/me | Профіль за Bearer Token |
| POST /enrollments | Запис на курс: { "courseId": 1 } |

Вхід і реєстрація обмежені 20 запитами за 5 хвилин на IP. Перевищення повертає 429 і Retry-After. POST-запити з чужим Origin відхиляються. Помилки не розкривають внутрішніх винятків.

Для свого бекенду скопіюйте .env.example у .env, задайте VITE_API_BASE_URL і перезапустіть Vite. Його контракти авторизації та CORS мають відповідати цьому frontend. VITE-змінні доступні у клієнтському коді; секрети в них не зберігаються.

## Короткий звіт: Access Token, Refresh Token та cookies

**Access Token** підтверджує доступ до захищених ресурсів. Тут це непрозорий випадковий токен на 15 хвилин. Він зберігається в пам’яті JavaScript і передається в Authorization, а не у localStorage.

**Refresh Token** дозволяє отримати новий Access Token. У цьому проєкті роль довшого облікового даного виконує випадковий ідентифікатор серверної сесії в HttpOnly cookie course_session. Її строк — 7 днів; сервер може відкликати її при виході. Cookie надсилається лише на /api/auth, а звичайні ресурсні endpoint перевіряють Bearer Token. [OAuth 2.0](https://www.rfc-editor.org/rfc/rfc6749.html#section-1.5).

**localStorage** доступний JavaScript того самого origin і зберігає дані після закриття вкладки. XSS може викрасти токен. Зберігання Access Token у пам’яті скорочує строк його перебування в браузері, але не робить застосунок невразливим до XSS. [OWASP Web Storage](https://cheatsheetseries.owasp.org/cheatsheets/HTML5_Security_Cheat_Sheet.html#local-storage).

**HttpOnly** не дозволяє прочитати cookie через document.cookie. Cookie встановлює сервер. Вона має SameSite=Lax, Path=/api/auth та Secure при HTTPS; локальний HTTP працює без Secure. Браузер надсилає cookies автоматично, тому потрібно враховувати CSRF: тут перевіряється Origin для POST і встановлено SameSite. HttpOnly не заважає XSS виконувати дії від імені користувача. Для cross-origin потрібні credentials, конкретний origin у CORS і врахування правил SameSite та обмежень сторонніх cookies. [MDN Set-Cookie](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Set-Cookie).

## Перевірки

Три серверні тести перевіряють збереження акаунтів, сольові хеші, парольні помилки, незалежність курсів, дублікати email при одночасних запитах, строк дії Access Token, refresh і відкликання при виході.

У браузері перевірено:
- Валідацію, показ пароля, реєстрацію та автоматичний вхід.
- Неправильний пароль і повторну адресу незалежно від регістру.
- Запис на курс, профіль і збереження входу після оновлення сторінки.
- Відновлення трьох одночасних запитів через один refresh.
- Повний вихід і відсутність входу після перезавантаження.
- Окремі акаунти, мобільну верстку та відсутність токенів у localStorage/sessionStorage.
- Захист локального файлу даних від HTTP-завантаження: 403.

Довідка: [Axios interceptors](https://axios-http.com/docs/interceptors), [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html).
